## 📌 Обзор проекта

**News Aggregator** — это автоматизированная система сбора, анализа и публикации новостей с использованием AI-агентов.

### Источники данных
| Источник | Технология | Частота |
|----------|------------|---------|
| Telegram-каналы | Telethon (UserBot) | Реальное время |
| RSS/Atom ленты | feedparser | Каждые 5 мин |
| Web-сайты | requests + BeautifulSoup4 | Каждые 60 мин |

### Ключевые возможности
- ✅ Мониторинг Telegram-каналов в реальном времени
- ✅ Автоматическая категоризация и оценка срочности (1-5)
- ✅ Генерация сводных новостей через AI-агентов (Analyst → Editor → Archivist)
- ✅ Векторный поиск похожих событий (ChromaDB + sentence-transformers)
- ✅ Публикация в Telegram-каналы
- ✅ Платные подписки (Telegram Stars)
- ✅ 2FA аутентификация (TOTP) для администраторов
- ✅ Web-админка (FastAPI + JWT)

## 🏗️ Архитектура системы

### Уровни архитектуры

```
┌─────────────────────────────────────────────────────────────────┐
│              PRESENTATION LAYER — СБОР НОВОСТЕЙ                  │
│  Admin Bot (aiogram)  │  Listener Bot (Telethon)  │  Scheduler  │
│  Web Admin (FastAPI)  │  RSS Parser  │  Web Parser               │
└─────────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┴─────────────────────┐
        ▼                                           ▼
┌─────────────────────────────────┐     ┌─────────────────────────┐
│       APPLICATION LAYER         │     │    DOMAIN LAYER         │
│  NewsOrchestrator (координация) │     │  Strategies:            │
│  EventBus (приоритеты)          │     │  - Urgent (4-5)         │
│  AgentTaskQueue (AI очередь)    │     │  - Scheduled (1-3)      │
└─────────────────────────────────┘     │  - Trusted (доверенные) │
        │                               └─────────────────────────┘
        ▼
┌─────────────────────────────────────────────────────────────────┐
│                       SERVICE LAYER                              │
│  Categorization  │  News Generation  │  Vector Search           │
│  Payment         │  LLM Provider     │  Notification            │
└─────────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────────┐
│                  INFRASTRUCTURE LAYER                            │
│  Repository Pattern (8 repos)  │  Database (SQLite/PostgreSQL)  │
│  Vector Store (ChromaDB)       │  Redis (очередь)               │
└─────────────────────────────────────────────────────────────────┘
```

### Архитектурные принципы
| Принцип | Реализация |
|---------|------------|
| **Single Responsibility** | Каждый сервис имеет одну ответственность |
| **Dependency Injection** | DI контейнер (Container) |
| **Repository Pattern** | 8 репозиториев для доступа к данным |
| **Strategy Pattern** | 3 стратегии обработки новостей |
| **Event-Driven** | EventBus с приоритетами |
| **Explicit Dependencies** | Минимум глобальных состояний |

## 🧩 Ключевые компоненты

### 1. AI Агенты (services/ai_agent/)

| Агент | Задача | Промпт |
|-------|--------|--------|
| **Categorizer** | Первичная классификация, фильтрация рекламы | prompts/categorizer.txt |
| **Analyst** | Оценка категории + confidence, тэгирование | prompts/analyst.txt |
| **Editor** | Генерация новости в журналистском стиле | prompts/editor.txt |
| **Archivist** | Структурирование контекста для векторного поиска | prompts/archivist.txt |

### 2. Обработка новостей (services/news/)

```
Scheduler → NewsOrchestrator → Strategy
                                 │
         ┌───────────────────────┼────────────────┐
         ▼                       ▼                ▼
  UrgentNewsStrategy     ScheduledNews     TrustedSource
  (срочность 4-5)        (срочность 1-3)   (доверенные)
         │                       │                │
         ▼                       ▼                ▼
  Analyst → EventBus       Сохранение      Публикация
  Editor → Archivist       в БД            напрямую
  Moderation
```

### 3. Категоризация (services/categorization/)

```
ListenerBot → CategorizationQueue → CategorizationProcessor
                                      ├─ CategorizerAgent (AI)
                                      ├─ NewsClassifier (парсинг)
                                      ├─ NewsSaver (БД)
                                      └─ NotificationService
```

### 4. База данных (database/)

#### Модели данных
| Модель | Таблица | Описание |
|--------|---------|----------|
| Channel | channels | Telegram-каналы для мониторинга |
| TelegramPost | posts | Посты из Telegram |
| GeneratedNews | generated_news | Сгенерированные AI новости |
| EventContext | events | Контексты событий |
| Publisher | publishers | Каналы для публикации |
| User | users | Пользователи бота (с 2FA) |
| Task | tasks | Задачи планировщика |
| RSSSource / RSSNews | rss_sources / rss_news | RSS источники и новости |
| WebSource / WebNews | web_sources / web_news | Web источники и новости |

#### Репозитории (8)
- `channels.py` — управление каналами
- `posts.py` — управление постами
- `news.py` — управление новостями
- `events.py` — управление событиями
- `publishers.py` — управление издателями
- `users.py` — управление пользователями
- `tasks.py` — управление задачами

### 5. Планировщик (services/scheduler/)

**Архитектура v4.0:** Планировщик только выполняет задачи из таблицы `tasks`.

| Задача | Описание | Интервал |
|--------|----------|----------|
| Task Processor | Обработка задач из БД | Каждые 10 сек |
| EventBus | Шина событий | Непрерывно |
| RSS Parser | Парсинг RSS лент | Каждые 5 мин |
| Expired Cleaner | Очистка старых задач | Каждые 5 мин |
